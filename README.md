## Webpack vs Vite

У межах проєкту Library було реалізовано дві версії збірки: початкову версію з Webpack та окрему гілку `vite-migration`, у якій Webpack було замінено на Vite. Функціональність застосунку при цьому залишилася без змін: TypeScript, Bootstrap, SCSS, пошук книг, пагінація, робота з користувачами та книгами.

### 1. Швидкість запуску dev-сервера та HMR

Webpack перед запуском dev-сервера спочатку формує bundle проєкту, тому запуск залежить від кількості модулів і налаштувань збірки.

Vite використовує інший підхід: під час розробки модулі обробляються за потреби, тому dev-сервер запускається швидше. Також Vite має швидкий HMR (Hot Module Replacement), що дозволяє швидко бачити зміни в браузері без повної перебудови всього застосунку.

Для цього невеликого проєкту різниця не є критичною, однак Vite має простішу та швидшу модель запуску development-середовища.

### 2. Налаштування конфігурації

Webpack потребував окремого `webpack.config.js`, у якому потрібно було налаштовувати entry point, output, TypeScript loader, CSS/SCSS loaders, HTML plugin та dev-server.

Для Vite достатньо було створити `vite.config.mts` і налаштувати dev-server та production build. TypeScript і SCSS підтримуються Vite без необхідності окремо підключати `ts-loader`, `css-loader`, `style-loader` та `sass-loader`.

Таким чином, у межах цього проєкту конфігурація Vite виявилася значно коротшою та простішою.

### 3. Production-збірка

Обидва інструменти створюють production-збірку з оптимізованими JavaScript та CSS файлами.

У Vite після міграції команда:

```bash
npm run build
```

успішно створила production-збірку. Результат містив:

* `dist/index.html`
* JavaScript bundle
* CSS bundle

Збірка Vite у цьому проєкті виконувалася приблизно за 3 секунди. Розмір згенерованих файлів також залишався невеликим для такого SPA.

Водночас пряме порівняння часу Webpack і Vite у цьому проєкті не є повністю точним, оскільки результати залежать від конфігурації, кешування, версій інструментів та середовища запуску.

### 4. Підключення UI-фреймворку та TypeScript

У проєкті використовується Bootstrap разом із SCSS.

У Webpack для обробки TypeScript та стилів потрібно було використовувати окремі loaders, зокрема `ts-loader`, `css-loader`, `style-loader` та `sass-loader`.

У Vite TypeScript підтримується без окремого TypeScript loader, а SCSS підключається через встановлений пакет `sass`. Bootstrap також продовжив працювати без зміни основної логіки застосунку.

Тому для цього проєкту підключення TypeScript та Bootstrap/SCSS у Vite виявилося простішим.

### 5. Екосистема плагінів

Webpack має дуже велику та зрілу екосистему loader-ів і plugin-ів. Це дозволяє детально налаштовувати практично всі етапи процесу збірки.

Vite також має велику екосистему плагінів і підтримує популярні frontend-технології. Крім того, Vite використовує Rollup-підхід для production-збірки, що забезпечує доступ до відповідної екосистеми інструментів.

Для невеликого TypeScript SPA, подібного до Library, можливостей Vite достатньо для реалізації необхідного функціоналу без складної конфігурації.

### 6. Зручність для невеликих SPA-проєктів

Для цього проєкту Vite виявився простішим у використанні. Основною причиною є менша кількість конфігурації та відсутність необхідності вручну налаштовувати loaders для TypeScript і стилів.

Webpack має перевагу тоді, коли потрібен детальний контроль над процесом збірки або складна кастомізація. Однак для невеликого SPA з TypeScript, Bootstrap та SCSS така кількість налаштувань не є необхідною.

### Висновок

У результаті міграції проєкту Library з Webpack на Vite було збережено всю функціональність застосунку та успішно налаштовано development і production-збірку. Після міграції `npm run build`, `npm run lint` та всі 6 автоматизованих тестів виконуються успішно.

Webpack є потужним та гнучким інструментом із великою екосистемою, але його конфігурація для цього проєкту була більшою та вимагала окремих loaders і plugins.

Vite потребував значно меншої конфігурації та спростив роботу з TypeScript і SCSS. Для невеликих SPA-проєктів, подібних до Library, Vite є зручним варіантом завдяки швидкому dev-серверу, HMR та простішому налаштуванню.

Таким чином, для подібного невеликого SPA-проєкту особисто для мене Vite виявився зручнішим у повсякденній розробці, тоді як Webpack залишається більш гнучким рішенням для складних і сильно кастомізованих процесів збірки.
